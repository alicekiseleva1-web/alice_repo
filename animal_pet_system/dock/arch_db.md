# Проектирование базы данных

## Назначение

PostgreSQL хранит данные системы поиска пропавших домашних животных и помощи приютам. База данных содержит пользователей, животных, приюты, объявления, фотографии, сообщения и заявки помощи, а также справочники и SQL-функции для работы API.

## Схемы

В базе создаются четыре схемы:

- `dict` — справочные значения;
- `main` — таблицы предметной области и бизнес-логика;
- `api` — функции, вызываемые приложением;
- `auth` — резервная схема, в текущей версии таблиц не содержит.

Пароли не хранятся в отдельной таблице авторизации: хэш пароля находится в поле `main.user.password_hash`.

## Справочники `dict`

| Таблица | Назначение |
|---|---|
| `city` | Города: `city_id`, название и уникальный FIAS ID |
| `gender` | Пол животного |
| `animal_status` | Статусы животного |
| `report_type` | Типы объявлений |
| `report_status` | Статусы объявлений |
| `user_role` | Роли пользователей |
| `user_status` | Статусы пользователей |
| `help_request_status` | Статусы заявок помощи |

API передаёт идентификаторы справочников, например `city_id`, `gender_id` и `report_type_id`, а не текстовые коды.

Таблица `dict.city` содержит поле `fias_id` с ограничением уникальности. Город выбирается из подсказки DaData; повторный выбор города с тем же FIAS ID обновляет существующую запись, а не создаёт дубль.

## Основные таблицы `main`

### Пользователь `main.user`

Хранит имя, фамилию, город, телефон, email, хэш пароля, роль, статус и дату регистрации.

- `city_id` связан с `dict.city`;
- `role_id` связан с `dict.user_role`;
- `user_status_id` связан с `dict.user_status`;
- email и телефон уникальны.

### Животное `main.animal`

Хранит владельца, кличку, породу, пол, возраст, окрас, город, описание, статус и даты создания и изменения статуса.

- `owner_id` связан с `main.user`;
- `gender_id` связан с `dict.gender`;
- `city_id` связан с `dict.city`;
- `animal_status_id` связан с `dict.animal_status`.

### Приют `main.shelter`

Хранит название приюта, город, адрес, контакты, описание и дату создания. `city_id` связан с `dict.city`, а `manager_user_id` — с аккаунтом сотрудника приюта. На один аккаунт может приходиться не более одного приюта.

### Объявление `main.report`

Хранит автора, животное, тип, статус, заголовок, описание, место и даты создания, изменения и закрытия.

- `user_id` связан с `main.user`;
- `animal_id` связан с `main.animal`;
- `report_type_id` связан с `dict.report_type`;
- `report_status_id` связан с `dict.report_status`.

В `dict.report_type` хранятся `lost`, `found`, `help` и `adoption` («Ищет дом»). Для `adoption` функции списка и карточки возвращают название приюта через связь автора с `main.shelter.manager_user_id`; без такой связи возвращается `null`. Остальные типы не получают пометку о нахождении животного в приюте.

### Фотография `main.photo`

Хранит URL фотографии, животное, необязательное объявление и дату добавления.

### Сообщение `main.message`

Хранит объявление, автора сообщения, текст и дату создания.

### Заявка помощи `main.help_request`

Хранит приют, автора, заголовок, описание, статус и даты создания и изменения.

## Связи между сущностями

```text
dict.city 1 ─── N main.user
dict.city 1 ─── N main.animal
dict.city 1 ─── N main.shelter

main.user 1 ─── N main.animal
main.user 1 ─── N main.report
main.user 1 ─── N main.message
main.user 1 ─── 0..1 main.shelter

main.animal 1 ─── N main.report
main.animal 1 ─── N main.photo

main.report 1 ─── N main.message
main.report 1 ─── N main.photo

main.shelter 1 ─── N main.help_request
main.user 1 ─── N main.help_request
```

## Индексы

Для частых запросов созданы индексы по:

- городу и статусу животного;
- статусу, типу, животному и автору объявления;
- объявлению сообщения;
- приюту и статусу заявки помощи.
- FIAS ID города обеспечивается уникальным ограничением таблицы `dict.city`.

## SQL-функции

Логика разделена на два уровня:

- функции `main.*` содержат проверки и операции с таблицами;
- функции `api.*` вызываются сервисами FastAPI и передают параметры в `main.*`.

Реализованы функции для:

- регистрации пользователя или сотрудника приюта, проверки учётных данных и получения карточки пользователя;
- создания животного, изменения его статуса и получения карточки;
- создания, получения списка, просмотра и закрытия объявлений, а также изменения статуса автором и вывода его объявлений в профиле;
- создания и получения сообщений;
- добавления и получения фотографий;
- создания, получения и изменения статуса заявок помощи;
- разрешения города по FIAS ID через `main.resolve_city` и `api.resolve_city`. При неоднозначных старых записях без FIAS ID функция возвращает ошибку и не создаёт новый дубль.
- получения и редактирования карточки приюта, привязанного к сотруднику.

## Скрипты базы данных

| Файл | Назначение |
|---|---|
| `01_create_user.sql` | Создание роли PostgreSQL для учебного окружения |
| `02_create_database.sql` | Создание базы данных `animal_help` |
| `03_create_schemas.sql` | Создание схем `auth`, `api`, `main`, `dict` |
| `04_create_tables.sql` | Создание таблиц и внешних ключей |
| `05_create_indexes.sql` | Создание индексов |
| `06_create_functions.sql` | Создание SQL-функций предметной области |
| `07_insert_dict.sql` | Начальное заполнение статусов, ролей, типов объявлений и пола животных |
| `08_test_data.sql` | Необязательные тестовые данные для чистой базы |

Для чистой базы скрипты применяются в порядке от `01` до `08`. Скрипты `07` и `08` не следует повторно запускать на уже заполненной базе, так как они рассчитаны на первичное наполнение.

`00_drop_all.sql` не входит в обычный сценарий запуска. Это служебный скрипт сброса окружения, который требует отдельной доработки перед использованием.

## Работа с паролями

Приложение хэширует пароль алгоритмом PBKDF2-HMAC-SHA256 до вызова SQL-функции регистрации. В базу передаётся только хэш.

Тестовые пользователи из `08_test_data.sql` содержат старые условные значения в поле `password_hash`, поэтому они подходят для проверки связей и выборок, но не для входа через текущий маршрут `/login`.
