# Тестирование

В проекте используются автоматические модульные тесты серверной части, ручные проверки интерфейса, API и SQL-функций. Документ содержит порядок запуска, сценарии и результаты проверок.

## Модульные тесты

Тесты находятся в `back/tests` и используют стандартный модуль Python `unittest`. Перед запуском устанавливаются зависимости из `back/requirements.txt`; дополнительные пакеты для тестирования не требуются.

Команда запуска из корня `animal_pet_system`:

```powershell
.\back\venv\Scripts\python.exe -m unittest discover -s back/tests -t back -v
```

| Файл | Количество тестов | Область проверки |
|---|---:|---|
| `test_security.py` | 8 | Формат хэша, случайная соль, правильные и неправильные пароли, Unicode, значимость пробелов, некорректные хэши |
| `test_user_schemas.py` | 19 | Регистрация пользователя и приюта, длина пароля, поля профиля, смена пароля, длина запроса города и FIAS ID |
| `test_domain_schemas.py` | 10 | Схемы животных, объявлений, приютов, заявок помощи и фотографий; обязательные поля, диапазоны и лишние поля |
| `test_images.py` | 12 | MIME-тип, пустой файл, граница размера 5 × 1024 × 1024 байт, положение потока, параметры загрузки и обработка ответов и ошибок Cloudinary |
| **Итого** | **49** | **Все тесты пройдены** |

Количество соответствует тестовым методам; варианты внутри `subTest` отдельно не учитываются.

Проверки выполняются без подключения к PostgreSQL, DaData и Cloudinary и без запуска серверов. Настройка Cloudinary и вызовы его SDK заменены тестовыми объектами с помощью `unittest.mock`; реальные изображения не загружаются и не удаляются. Хэширование паролей выполняется реальными функциями приложения.

Тесты изображений проверяют объявленный MIME-тип и размер потока, но не декодирование содержимого изображения. Проверки схем не подтверждают существование переданных ID в БД. HTTP-коды, SQL-ограничения, лимит количества фотографий, интерфейс и реальные внешние интеграции проверяются отдельно по сценариям ниже.

## Подготовка окружения

Проверки с изменением данных выполняются в отдельной тестовой базе. Инициализация схем рабочей базы `animal_help` в рамках тестирования не допускается. Для проверки внешних интеграций используются тестовые данные и изображения, предназначенные для последующего удаления. Загрузка в Cloudinary создаёт файлы в облачном хранилище и расходует доступную квоту; SQL `ROLLBACK` не отменяет эту операцию.

Предусловие функциональных сценариев — регистрация двух обычных пользователей A и B и сотрудника приюта S. Идентификаторы `user_id`, `animal_id`, `report_id`, `request_id` фиксируются по ответам API; конкретные числовые значения заранее не предполагаются. SQL-примеры из `db/тестовые вызовы.sql` выполняются в отдельной базе с начальным наполнением из скриптов `07` и `08`.

Для регистрации используются уникальные тестовые email и телефоны. Пароли тестовых аккаунтов не совпадают с паролями внешних сервисов и не включаются в протокол. Для проверок редактирования пользователь A должен иметь животное и открытое объявление, а S — связанный приют. Для сценариев фотографий используется отдельное животное A; исходное количество снимков устанавливается согласно проверяемому случаю.

Сценарии выполняются независимо, если последовательность прямо не указана в шаге. После смены email или пароля следующие проверки используют актуальные данные. Закрытые в ходе проверки объявления и заявки перед повторным использованием возвращаются в требуемое исходное состояние.

## Проверки сборки и запуска

Из каталога `front`:

```powershell
npm run lint
npm run build
```

Проверка Python-зависимостей и синтаксиса из корня проекта, без подключения к БД:

```powershell
.\back\venv\Scripts\python.exe -m pip check
.\back\venv\Scripts\python.exe -m compileall -q back/app back/tests
```

После запуска обоих серверов:

1. `GET /` возвращает `200` и `{"message":"server works"}`.
2. `GET /db-test` возвращает имя именно выбранной базы.
3. `/docs` показывает маршруты, `/openapi.json` — схему API.
4. `http://localhost:5173/` открывается, список объявлений загружается без ошибки сети.

| Проверка | Результат |
|---|---|
| Совместимость Python-зависимостей | Конфликтов не обнаружено |
| Компиляция Python-файлов | Ошибок не обнаружено |
| ESLint | Ошибок не обнаружено |
| Сборка Vite | Выполнена успешно |

Результаты относятся к проверке кода и сборки, а не к функциональным сценариям.

## Функциональные сценарии

Уровень «Интерфейс» означает выполнение в браузере. Уровень «API» означает отправку запроса через Swagger; остальные обязательные поля должны содержать корректные значения. HTTP-коды проверяются по ответу API, а не по результату клиентской проверки формы. SQL-проверки используются только для чтения состояния тестовой базы, если не указано иное.

Обозначения: U — пользователи, C — города, A — животные, R — объявления, P — фотографии, H — помощь приютам, M — сообщения, L — личный кабинет.

Результаты ручных проверок указаны по подтверждению автора проекта. «Пройдено» — результат соответствует ожидаемому; «Частично» — проверена только указанная часть сценария; «Не подтверждено» — результат отдельной проверки не зафиксирован.

## SQL-проверки

В отдельной базе последовательно создаются структура и тестовые данные, после чего выполняются [тестовые вызовы](../db/тестовые%20вызовы.sql). Запросы чтения возвращают справочники, карточки и списки. Блок изменения данных выполняется целиком, от `BEGIN` до `ROLLBACK`.

После отката транзакции количество строк в `main.photo`, `main.message`, `main.help_request` и значения изменённых полей должны совпасть с исходными. Пропуски в последовательностях ID допустимы: PostgreSQL не возвращает выданные значения последовательностей после отката.

При остановке выполнения скрипта из-за ошибки внутри транзакции требуется выполнить `ROLLBACK` вручную. Скрипт не содержит автоматических проверок ожидаемых значений; результаты запросов проверяются вручную.

| Проверка | Зафиксированный результат |
|---|---|
| Установка SQL | После создания схем скрипты `04`–`08` выполнены успешно в отдельной новой БД |
| Тестовые вызовы | Сценарий выполнен целиком |
| Состояние после отката | Проверенные записи `dict.city`, `main.user`, `main.animal`, `main.photo`, `main.message`, `main.help_request` совпали с исходными |

Эти результаты не подменяют отдельные проверки API и SQL из таблицы функциональных сценариев.
