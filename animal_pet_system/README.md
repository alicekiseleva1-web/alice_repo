# Система поиска животных и помощи приютам

«Найди друга» — учебное веб-приложение для поиска потерянных животных, поиска дома для животных и публикации заявок помощи приютам.

Проект состоит из клиентского приложения на React, REST API на FastAPI и базы данных PostgreSQL. DaData предоставляет подсказки городов, Cloudinary хранит загруженные фотографии. В PostgreSQL сохраняются внутренние ID городов и ссылки на изображения.

## Реализованные возможности

- регистрация пользователя или представителя приюта и вход по email и паролю;
- хэширование паролей и сохранение выбранного аккаунта между обновлениями страницы;
- выбор города через DaData и разрешение города по FIAS ID без повторного создания той же записи;
- создание объявлений «Пропало животное», «Найдено животное» и «Ищет дом»;
- список объявлений с фильтром по типу, подробности в модальном окне и название приюта для его объявлений о поиске дома;
- каталог животных с вкладками, поиском по кличке, породе и городу, постраничной загрузкой;
- до двух фотографий животного, увеличение и перелистывание, добавление, замена и удаление через личный кабинет;
- личный кабинет с вкладками «Мои животные» и «Мои объявления»: редактирование, закрытие и повторное открытие объявлений;
- редактирование имени, фамилии, телефона, email, города и отдельная смена пароля с проверкой текущего;
- редактирование названия, адреса и описания своего приюта;
- отдельная страница помощи приютам с категориями, публикацией, редактированием и изменением статуса заявок.

Дополнительно через API доступны сообщения к объявлениям, изменение статуса животного и фильтрация объявлений по ID города. Веб-интерфейс переписки не реализован.

## Быстрый запуск настроенного проекта

Для запуска настроенного проекта используются два терминала PowerShell, открытые в корне `animal_pet_system`. Предусловия: зависимости установлены, база данных подготовлена, `back/.env` заполнен, PostgreSQL запущен.

Первый терминал — API:

```powershell
cd back
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Второй терминал — веб-интерфейс:

```powershell
cd front
npm run dev
```

- Приложение: [http://localhost:5173/](http://localhost:5173/).
- Swagger: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Терминалы остаются открытыми на время работы приложения. Остановка каждого сервера выполняется сочетанием `Ctrl+C` в соответствующем терминале. Первичная подготовка описана ниже; повторное выполнение SQL-скриптов при обычном запуске не требуется.

## Требования к окружению

- Python 3.13 с `pip` и модулем `venv`.
- Node.js 24 и npm.
- PostgreSQL; SQL-скрипты проверялись на PostgreSQL 18.
- Клиент PostgreSQL, например DBeaver, для выполнения SQL-скриптов.
- Ключ DaData для выбора городов и настройки Cloudinary для загрузки фотографий.

Python-зависимости перечислены в `back/requirements.txt`. Зависимости интерфейса задаются в `front/package.json`, а разрешённые версии фиксируются в `front/package-lock.json`. Python-пакеты устанавливаются в виртуальное окружение, пакеты фронтенда — через npm.

## Подготовка базы данных

Для работы нужен локальный сервер PostgreSQL и база данных, параметры которой указаны в `back/.env`.

Скрипты в папке `db` разделены по назначению:

- `01_create_user.sql` и `02_create_database.sql` создают учебную роль PostgreSQL и базу данных;
- `03_create_schemas.sql`–`06_create_functions.sql` создают схемы, таблицы, индексы и SQL-функции;
- `07_insert_dict.sql` заполняет статусы, роли, типы объявлений, пол животных и категории помощи;
- `08_test_data.sql` добавляет необязательный тестовый город, пользователей, животных, приют и объявления.

Город при регистрации выбирается из подсказок DaData. `FIAS ID` — его канонический идентификатор: он не позволяет создать второй город при повторном выборе той же подсказки.

Первичная установка выполняется только в отдельной пустой базе:

1. Создать роль с помощью `01_create_user.sql`, если она отсутствует. Пароль в скрипте является учебным примером и подлежит замене при настройке окружения.
2. Выполнить `02_create_database.sql` из подключения к служебной базе `postgres`, вне транзакции. Переключить подключение на созданную базу `animal_help`.
3. Выполнить `03_create_schemas.sql`: он создаёт схемы `auth`, `api`, `main`, `dict` без удаления существующих объектов и данных.
4. Последовательно выполнить `04_create_tables.sql`, `05_create_indexes.sql`, `06_create_functions.sql`, `07_insert_dict.sql`.
5. При необходимости выполнить `08_test_data.sql`. Пользователи с `test_hash` предназначены для проверки связей и выборок, но не для входа. Учётные записи для демонстрации регистрируются через веб-интерфейс или Swagger. Ссылки `example.com` в тестовых фотографиях являются заглушками.

Скрипты `04`–`08` предназначены для первичной установки, а не для универсального обновления рабочей базы. Повторное выполнение `07`/`08` может вызвать ошибки уникальности. Для обновления существующей базы требуется отдельный SQL-сценарий, учитывающий установленную структуру; актуальная структура для новой установки поддерживается в основных файлах.

`00_drop_all.sql` не входит в первичную установку и обычный запуск. Это отдельный сценарий полного сброса: он удаляет схемы проекта со всеми данными и зависимыми объектами через `CASCADE`. После сброса структура создаётся скриптами `03`–`07`, тестовые данные — необязательным `08`. Скрипт не восстанавливает удалённые данные. Git сохраняет файлы проекта, но не строки PostgreSQL: перед намеренным сбросом или изменением рабочей БД требуется отдельная резервная копия.

## Настройка бэкенда

1. Перейти в каталог `back`.
2. Создать виртуальное окружение и установить зависимости.

```powershell
cd back
py -3.13 -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команды используют Python из виртуального окружения напрямую; активировать окружение в PowerShell не требуется.

3. Создать файл `.env` рядом с `.env.example` и заполнить параметры подключения.

Из каталога `back` можно скопировать шаблон командой ниже. Существующий `.env` она не перезаписывает:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

В созданном `.env` значения-заглушки заменяются параметрами локального окружения:

```text
DB_HOST=localhost
DB_PORT=5432
DB_NAME=animal_help
DB_USER=postgres
DB_PASSWORD=пароль_пользователя_PostgreSQL
DADATA_API_KEY=ключ_DaData
CLOUDINARY_CLOUD_NAME=название_облака
CLOUDINARY_API_KEY=ключ_Cloudinary
CLOUDINARY_API_SECRET=секрет_Cloudinary
```

`DB_USER` должен соответствовать используемой роли PostgreSQL: например, `animal_user` после выполнения `01`/`02` либо отдельно настроенной роли. Значение `postgres` приведено как пример. Файл `.env` исключён из Git; реальные пароли и ключи не должны включаться в репозиторий, текст работы или скриншоты.

`back/app/db.py` читает `back/.env` в UTF-8. Переменные окружения процесса имеют приоритет над файлом. После изменения настроек требуется перезапуск API. Ранее заданные в терминале переменные необходимо обновить или удалить отдельно: содержимое `.env` их не переопределяет.

4. Запустить API.

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

После запуска доступны:

- Swagger: <http://127.0.0.1:8000/docs>
- проверка сервера: <http://127.0.0.1:8000/>
- проверка базы данных: <http://127.0.0.1:8000/db-test>

## Настройка фронтенда

Установка зависимостей и запуск выполняются во втором терминале из корня проекта:

```powershell
cd front
npm ci
npm run dev
```

Команда `cd front` выполняется из корня `animal_pet_system`, не из `back`. Для воспроизведения зависимостей используется `package-lock.json`. В рабочем окружении используется Node.js 24; установленные версии можно проверить командами `node --version` и `npm --version`.

Vite выводит адрес приложения в терминале. Текущая настройка CORS разрешает origin <http://localhost:5173/>. Если порт занят и Vite выбрал другой, требуется освободить порт 5173 либо согласованно изменить адрес фронтенда и настройку CORS. Адрес API задан в `front/src/App.jsx`: `http://127.0.0.1:8000`.

При последующих запусках достаточно запустить PostgreSQL, запустить API из `back` и выполнить `npm run dev` из `front` в другом терминале. Оба терминала должны оставаться открытыми. Повторно создавать БД и устанавливать зависимости каждый раз не требуется.

Для проверки кода и сборки интерфейса из каталога `front`:

```powershell
npm run lint
npm run build
```

## Проверка функциональности

Модульные тесты серверной части запускаются из корня `animal_pet_system` после установки Python-зависимостей:

```powershell
.\back\venv\Scripts\python.exe -m unittest discover -s back/tests -t back -v
```

Набор содержит 49 тестов: хэширование и проверка паролей, валидация схем, ограничения загружаемых файлов и обработка ответов Cloudinary. Используется стандартный модуль Python `unittest`; отдельные тестовые зависимости не требуются. PostgreSQL, запущенный API и ключи внешних сервисов не нужны: вызовы Cloudinary заменены тестовыми объектами. Эти проверки не заменяют тестирование HTTP-маршрутов, SQL-функций и интерфейса.

- Проверка совместимости установленных Python-зависимостей из `back`: `.\venv\Scripts\python.exe -m pip check`.
- В Swagger можно проверить все доступные HTTP-маршруты.
- В `db/тестовые вызовы.sql` находятся SQL-проверки для DBeaver.
- Операции, изменяющие данные в этом SQL-файле, обёрнуты в транзакцию с `ROLLBACK`; выполнять их следует только в тестовой базе. Значения последовательностей после `ROLLBACK` не откатываются.
