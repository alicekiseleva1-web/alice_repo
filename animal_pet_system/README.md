# Система поиска животных и помощи приютам

Веб-приложение помогает публиковать объявления о потерянных и найденных животных, хранить карточки животных, обмениваться сообщениями по объявлениям и создавать заявки помощи приютам.

Проект состоит из клиентского приложения на React, REST API на FastAPI и базы данных PostgreSQL. Для выбора города при регистрации сервер получает подсказки из DaData и сохраняет внутренний идентификатор города в базе данных.

## Реализованные возможности

- регистрация и вход по email и паролю;
- хэширование паролей перед сохранением в PostgreSQL;
- поиск города через DaData при регистрации;
- создание и просмотр карточки животного;
- изменение статуса животного;
- создание, просмотр списка и карточки объявления;
- фильтрация списка объявлений по типу и городу;
- закрытие объявления;
- сообщения к объявлению;
- добавление и просмотр URL фотографий;
- создание, просмотр и изменение статуса заявок помощи приютам;
- интерактивный интерфейс списка объявлений, авторизации и регистрации.

## Подготовка базы данных

Для работы нужен локальный сервер PostgreSQL и база данных, параметры которой указаны в `back/.env`.

Скрипты в папке `db` разделены по назначению:

- `01_create_user.sql` и `02_create_database.sql` создают учебную роль PostgreSQL и базу данных;
- `03_create_schemas.sql`–`06_create_functions.sql` создают схемы, таблицы, индексы и SQL-функции;
- `07_insert_dict.sql` заполняет статусы, роли, типы объявлений и пол животных;
- `08_test_data.sql` добавляет необязательные тестовые данные;
- `09_dadata_city.sql` добавляет поддержку FIAS ID для DaData;
- `10_city_fias_upsert.sql` делает FIAS ID каноническим идентификатором города.

Города не заполняются вручную. Справочник `dict.city` пополняется только после выбора пользователем подсказки DaData.

Скрипты `07_insert_dict.sql` и `08_test_data.sql` предназначены для чистой базы. Не запускай их повторно в уже заполненной базе: это может вызвать ошибки уникальности.

`00_drop_all.sql` — служебный сценарий сброса окружения. Он не нужен для обычного запуска приложения и не должен выполняться на рабочей базе с данными.

## Настройка бэкенда

1. Перейди в папку `back`.
2. Создай виртуальное окружение и установи зависимости.

```bash
cd back
py -3.13 -m venv venv
source venv/Scripts/activate
pip install -r requirements.txt
```

В PowerShell вместо команды активации используй:

```powershell
.\venv\Scripts\Activate.ps1
```

3. Создай файл `.env` рядом с `.env.example` и заполни параметры подключения.

```text
DB_HOST=localhost
DB_PORT=5432
DB_NAME=animal_help
DB_USER=postgres
DB_PASSWORD=пароль_пользователя_PostgreSQL
DADATA_API_KEY=ключ_DaData
```

`DADATA_API_KEY` нужен только для подсказок городов. Не добавляй `.env` в Git.

4. Запусти API.

```bash
uvicorn app.main:app --reload
```

После запуска доступны:

- Swagger: <http://127.0.0.1:8000/docs>
- проверка сервера: <http://127.0.0.1:8000/>
- проверка базы данных: <http://127.0.0.1:8000/db-test>

## Настройка фронтенда

Открой второй терминал:

```powershell
cd front
npm install
npm run dev
```

Vite выведет адрес приложения. Обычно это <http://localhost:5173>.

Для проверки стиля кода:

```powershell
npm run lint
```

## Проверка функциональности

- В Swagger можно проверить все доступные HTTP-маршруты.
- В `db/тестовые вызовы.sql` находятся SQL-проверки для DBeaver.
- Операции, изменяющие данные в этом SQL-файле, обёрнуты в транзакцию с `ROLLBACK`.

Подробное описание маршрутов находится в [dock/arch_api.md](dock/arch_api.md), а схема и SQL-слой базы данных описаны в [dock/arch_db.md](dock/arch_db.md).
